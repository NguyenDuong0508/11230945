# Part 2 — Data Quality and Panel

## Scope and input contract

Read the sealed Bronze run through `active_source.json` in the Part 1 workspace. Reconcile its calendar, API totals, schema, file inventory and SHA-256 hashes using the Part 1 verifier before any transformation. A pending acquisition blocks execution. Use the authoritative financial partition paths from the Bronze manifest, not storage-benchmark replicas. No data download, outcome-based row removal or model training occurs here.

## Financial observations

The Silver panel is an observed, unbalanced bank–quarter panel, partitioned by reporting year and quarter. `CERT` and `REPDTE` remain its unique keys. Process quarters in order, sort by CERT, and use a per-CERT historical state containing only earlier reports. Do not generate missing bank–quarter rows, forward-fill across gaps, impute from the population, winsorize, or drop banks based on their eventual exit. The Bronze source is immutable; every original observation is retained in Silver.

Audit source missingness, zeros, negatives, nonfinite values, ranges, accounting relationships and extreme profitability ratios. The policy table lists the treatment and rationale for each flag. Nonpositive assets cannot be used as a positive size/ratio denominator: replace such values with null in Silver, retain the row and flag, and preserve the original value in Bronze. Nonfinite financial values are converted to null defensively (the Bronze contract normally rejects them). Negative equity and extreme ROE can be valid distress signals; retain and flag. Reporting gaps use exact calendar quarter indices. `REPORTS_TO_DATE` is an observed report count, not bank age.

### Capital reporting and income flows

`RBC1AAJ` and `RBCRWAJ` are distinct published capital ratios; do not treat them as interchangeable. The optional CBLR framework began in 2020 and removes some risk-based capital reporting requirements for qualifying electing institutions. The selected fields do not identify the actual election or historical non-applicability. The primary Silver values therefore retain zeros. `capital_audit.csv` reports zeros and missingness by quarter, pre/post-2020 regime, and non-null coverage in a separate hypothetical zero-as-missing scenario. No observation is classified as a CBLR elector from zero alone. The sensitivity scenario is not a correction to source data.

FDIC's reporting methodology distinguishes YTD Call Report income/expense from pre-2012 quarterly Thrift Financial Reports. It also documents merger-related adjustments. The selected API fields lack a verified historical basis identifier or merger-accounting adjustment for each observation. `NETINC`, `INTINC`, `EINTEXP`, `NONII` and `NONIX` are preserved as received. Columns ending `_Q_IF_YTD` provide a conditional calculation (Q1 unchanged; later quarters current minus exact adjacent same-year predecessor; null if the predecessor is missing). They must **not** enter the primary model unless field-level reporting semantics and comparability are verified. Pre-2012 versus 2012-onward coverage is reported separately; the candidate calculation is not a declaration that every historical source field is YTD. Negative flows are not necessarily errors. No differencing of published ROA, ROE or NIM ratios.

## Institutional events and exits

`event_ledger.parquet` is reference/outcome evidence, not a predictor table. One row is retained for each Failures source record, including missing CERTs, dates outside the study period and unknown transaction types. `RESTYPE` is normalized only for the classification: exact FAILURE means failure evidence, ASSISTANCE means assistance evidence, all other values are explicitly unresolved. `RESTYPE1` and FIN remain available for audit; do not infer failure solely from a resolution subtype or the endpoint name. The event date is parsed without silently converting malformed dates into valid events; date status and source text are retained. Link by positive CERT present in the panel, not institution name. Count source rows, unlinked records, duplicate FINs, distinct linked CERT/date combinations and timing conflicts separately. Duplicate source rows are not independent events. Source coverage does not guarantee that every event can be linked.

Institutions' ENDEFYMD closes the last structural event and can identify inactivity for closed institutions. It is retained as **candidate dated end evidence**, not proof of merger, liquidation, or failure. `ACTIVE` and `CHANGEC1` are current snapshot evidence only. Do not attach them to historical observations, infer a historical charter class, or treat a dated end as a proven merger without corroborating historical event records. The `terminal_audit.parquet` table distinguishes failure evidence, timing conflicts, dated end candidates, unresolved discontinuation, and observation at the study end. It uses full history and must never select modelling rows or be joined as predictors. Assistance does not establish a failure or exit. A reporting stop alone establishes neither.

## Time contract and outcome invariance

The panel retains report dates and `ASSUMED_AVAILABLE_AT = REPDTE + 90 calendar days`. These are not observed release timestamps; later amendments to historical reports are not observable from the acquired snapshot. `availability_sensitivity.csv` measures the proportion of observed reports that would be available at the same, next, and second subsequent quarter ends under 60/90/120/180-day assumptions. This is a source-report timing diagnostic, not a prediction-risk-set count. The downstream decision-date convention is quarter-end q, using only the latest report available by q (see `latest_available_report`). No requirement for a bank to be observed in a future quarter may define the risk set.

`horizon_outcome` is an executable reference policy and regression-test target; Part 2 does not persist a supervised label table or choose a split. Given an independently established risk set, a failure within (q, q+4] is positive unless directly conflicting evidence through that horizon prevents adjudication. Without a failure, an observed horizon-end report establishes follow-up; a gap with no report at the horizon is conservatively unresolved. A candidate institutional end without independently corroborated non-failure closure is censored by default; treating that candidate as a non-failure zero is a separate sensitivity option. A corroborated `verified_nonfailure_exit` (a reserved type for future dated evidence; Part 2 does not manufacture it) is zero in the binary target by default, with a separate competing-risk censoring sensitivity. A prior uncorroborated structural end date is not proof of historical ineligibility. A dated unknown event inside the horizon is uncertain. Undated/unlinked records cannot be allocated to arbitrary historical rows; quantify the resulting outcome completeness limitation and seek corroboration when feasible. Outcome adjudication must be restricted to evidence through the row's horizon, not full-history terminal classes. The final labelled quarter is no later than 2025Q2. Part 4 must establish the final risk set, adjudicate ambiguous dates, reconcile eligibility, and quantify actual failure counts in the chosen test period.

A regression case covers CERT 7213, 2006Q4 (horizon 2007Q4), with a subsequent assistance transaction. Appending dated events after the horizon must not change a previously determined outcome. The source-data case is evaluated only when the report is present; synthetic tests cover assistance, failure, boundary dates, unknown events and contradictory records. Report the actual diagnostic, not an expected result. The test does not establish historical publication vintages or complete event linkage.

## Execution, evidence and handoff

Run `python run_part2.py build --workspace PATH` followed by `python run_part2.py verify --workspace PATH`. The stage writes a fresh Silver run and publishes `active_panel.json` after reconciliation. The verifier recomputes deterministic financial transformations from the Bronze partitions, checks each output table and reference ledger, and verifies artifact inventory and hashes. A failed run does not publish a new pointer. Avoid concurrent runs in the same workspace. The independent verification reuses the specified transformation rules; it checks reproducibility, not the economic truth of all raw data.

Part 3 consumes the verified `panel/` partitions and the manifest inventory (use `resolve_panel`). Part 4 uses the same panel plus the separate dated event ledger, explicitly selects permitted predictors, and defines the decision-date risk set and labels. Conditional income candidates and retrospective reference fields are not automatically included. All learned transformations must be fitted on training folds only. No downstream model results are generated in Part 2.
